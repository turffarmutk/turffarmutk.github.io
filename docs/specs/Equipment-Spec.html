Equipment Module

A live status board for the farm's machines — what's available, in use, or down — with automatic checkout from tasks, one-tap problem reports that spawn a repair, and a service history per machine. Companion to the main plan, Task Board, Access & Roles, Inventory, and Crew Schedule specs.

1. What this module does

A live board of the farm's machines so anyone can see at a glance what's Available, In use, or Down — and who has what. Checkout happens automatically when a task starts, problems are reported in one tap and spawn a repair task, and each machine keeps a service history. It keeps Bill from discovering a mower is down when someone's already standing at it.

3. Equipment roster

A list of named machines — e.g. "Toro Triplex #3," "John Deere sprayer," "Dennis mower," "2653 mower," "backpack sprayer," "aerator," "utility tractor." Each machine is linked to the task-catalog types it performs, so the mower a job runs on is the same record tracked here.

Bill maintains the roster; retired machines are archived, not deleted, so their history stays intact.

5. Automatic checkout

Checkout rides the task

There's no separate "check out this machine" step. When a worker starts a task that uses a machine (the machine tied to that job — typically one per task), the app checks it out to them automatically: status → In use, holder = the worker, timestamped. On task completion it checks back in → Available.

The checkout log is simply these task-driven records — who had which machine, when, and for which task — so Bill can always see who last had a machine. (Non-task/manual checkout is out of scope for v1 — checkout is task-driven only.)

6. Problem reports

Report → repair task → confirm Down

A tech or grad taps Report a problem on a machine and describes the issue (undergrads route it through Bill instead). That report:

  • Flags the machine with an "issue reported" marker so people know it's questionable — but does not change its status on its own.
  • Auto-creates a repair task on the board, linked to the machine, and assigns it to Bill — sending the standard "task assigned to you" push (no new alert type).

Only Bill or a technician can confirm the machine doesn't work and set it Down. When the repair task is completed, the machine returns to Available automatically and the report closes.

7. Maintenance history

Each machine keeps a service history, built two ways:

  • Task-linked — completing a maintenance task tied to a machine (Grind Reels, Backlap Reels, Oil Change, a repair) writes an entry automatically.
  • Manual — Bill or a tech adds a service entry by hand (date, what was done, notes).

So the history captures both the routine jobs done through the task board and anything logged directly.

8. Screens (v1)

  1. Equipment list — all machines with status and current holder; filter by type/status; down machines flagged. Default screen.
  2. Machine detail — status, who has it, checkout log, maintenance history, linked catalog types, a Report a problem button (tech/grad), and a Confirm Down control (Bill/tech). Fixed is automatic on repair completion.
  3. Report a problem — description → flags the machine, spawns the repair task, alerts Bill (Bill or a tech then confirms Down if needed).
  4. Add / edit machine — Bill sets name, type, linked catalog types. Bill only.
  5. Add maintenance entry — manual service record (Bill/tech).

9. Notifications

  • Problem reported → the auto-created repair task is assigned to Bill, so he gets the standard "task assigned to you" push. No equipment-specific push type.
  • Down machines are flagged in-app on the board for everyone.

11. Out of scope for v1 (comes later)

  • Manual / non-task checkout (v1 checkout is task-driven only)
  • Photos on problem reports
  • Preventive/scheduled maintenance reminders (by hours or calendar)
  • Engine-hours / meter tracking and fuel-per-machine
  • Parts inventory linked to repairs
  • More than one machine per task

12. Decisions

  • Checkout: task-driven only — no manual checkout in v1.
  • Fixed: completing the repair task auto-returns the machine to Available.
  • Reporting & Down: undergrads route problems through Bill; techs/grads can report; only Bill or a technician confirms a machine Down.
  • Photos: not in v1.
