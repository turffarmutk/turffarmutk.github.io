Field-Ops Logging

The explicit record of operations performed on the farm — mowing, sprays, fertilizer, irrigation, and more — by plot and date, with the chemical applications kept to a compliance standard. Companion to the other module specs.

1. What this module does

A standalone operations log — a single place to record what was done, where, and when: mowing, pesticide and fertilizer applications, irrigation, aeration, topdressing, and the rest. Ops are entered explicitly here, and the chemical applications carry the extra fields needed for a clean chemical application record kept for compliance (a formal export is a later add). Anyone signed in can log an op, so the record stays complete.

2. Who can do what

RoleIn this module
Anyone signed inLog a non-chemical operation (mowing, irrigation, aeration, topdress, etc.); view the log; edit their own recent entries
Techs / grads / Bill (+ granted undergrads)Additionally log chemical & fertilizer applications — the same set allowed to make them
Bill (manager)All of the above, plus edit/correct any entry
Chemical logging is restricted: anyone can log a general op, but only people allowed to make chemical/fertilizer applications (techs, grads, Bill — undergrads only if Bill grants) can log one, keeping the compliance record trustworthy.

3. Operation types

The op-type picker reuses the Farm Task Catalog so names stay consistent — mowing variants, Spray Pesticide (JD / backpack) → herbicide/fungicide/insecticide, Spray Fertilizer, Fertilize (granular), Aeration, Traffic, Topdress, Handwater, Weedeat, Paint Trial Dots, etc. Each type drives which extra fields appear (§4).

5. Chemical application record

Any pesticide/fertilizer op is automatically part of the chemical application record — a compliance view kept in the log (a formal export/report is a later add). Only people allowed to make chemical applications can create these entries (§2). For v1 it captures: product, active ingredient, amount used, rate, target pest/weed, plots/area treated, applicator (the logged person), and date/time. Area treated is summed from the selected plots (interactive map). Fields like EPA reg #, REI/PHI, applicator license, and weather are noted for later (§9).

6. Relationship to tasks & inventory (important)

This log is the single operations record — tasks and inventory feed it so nothing is entered twice:

Inventory (sprays & fertilizer)

A chemical/fert op records a product + amount, which decrements the product's stock. It's one event: the field-ops entry and the inventory decrement are the same record, so stock drops once and is never double-counted.

Tasks (mowing auto-log)

Completing a mow task posts a field-ops entry here automatically — completing the task and logging the mow are the same record, no double entry.

Decided: field-ops is the one true operations log; task completion and inventory logging feed into it. The source field (manual / task / inventory) records how each entry arrived.

7. Screens (v1)

  1. Operations log — the filterable record (by plot/area, date, type, person, product). Default screen.
  2. Log an operation — the entry form (§4): pick type → map location → type-specific fields → save.
  3. Op detail — full entry, editable by its author (or Bill).

9. Out of scope for v1 (comes later)

  • EPA reg #, REI/PHI, and applicator license on the chemical record
  • Weather at time of application (auto-pull) — pairs with the Weather module
  • Per-op photos
  • Mowing height / clipping yield capture
  • Irrigation run-times / volumes

10. Decisions

  • Single record: tasks (mow auto-log) and inventory (spray/fert) feed this log — it's the one true operations record, no duplicate entry.
  • Chemical logging: anyone logs general ops, but only those allowed to make chemical/fertilizer applications (techs/grads/Bill, undergrads if granted) can log one.
  • Inventory decrement: a chemical/fert op decrements the product's stock once — the same event as the inventory usage entry, never double-counted.
