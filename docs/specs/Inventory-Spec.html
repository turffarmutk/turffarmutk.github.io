1. What this module does

A real-time stock list for the farm's inputs, so Bill always knows what's on hand and gets warned before anything runs out. The crew logs what they use and what comes in — quickly, via a shared QR that opens the logging form — and each item can be viewed as whole containers or a measured amount. Bill is alerted when an item drops to its reorder point.

2. Who can do what

Smart product entry — autofill from the brand name

To make setup as fast as possible, the module keeps a product reference list (brand name → active ingredient, category, formulation type, and resistance-group code). As someone types a brand name, it suggests matches and autofills those fields. Everything stays editable — if a match is wrong or the product isn't listed yet, they just type over it.

How the reference gets populated:

  • Seeded with the farm's commonly used products up front, so the big ones autofill from day one.
  • Self-learning — the first time a new product is entered by hand, it's saved to the reference so it autofills next time, for everyone.
  • Optional import — a public pesticide-product list could be loaded later to broaden coverage.
Build note: before launch we'll need to build a reference Excel sheet of the farm's products — brand name → active ingredient, category, formulation, and resistance-group code — to seed the product_reference table. This is the one real prep task behind autofill; the self-learning fills gaps from there.

4. Counting stock — containers or measured amount

Stock can be viewed two ways, with a toggle to switch between them:

  • Containers — whole units on the shelf (e.g. 3 jugs, 5 bags, 8 cans). Fast to eyeball.
  • Measured amount — volume/weight (e.g. 7.5 gal, 250 lb, 6 lb of seed). Precise for partial containers and applications.

The item's container size converts between the two (1 jug = 2.5 gal → 3 jugs = 7.5 gal). Under the hood a single quantity is stored; the toggle just changes how it's shown, so the two never disagree. Containers can be fractional (a half-used jug = 0.5), since the measured amount is the source of truth. For products with multiple container sizes, the measured amount still rules and the containers view shows the breakdown by size (e.g. 2 × 2.5 gal jugs + 1 × 30 gal drum).

5. Logging usage & restocks

Because the farm carries too many items to label each one, there is no per-item QR. Instead a single shared QR — posted where it's handy (chem room wall, on the sprayer, at the mix station) — opens the logging screen. From there the user picks what they're doing and which product. The same screen is reachable in-app without scanning.

Step 1 — Open the logging screen (two ways in)

So a lost, damaged, or unreachable QR never blocks logging, there are two entry points:

  • Scan the posted QR — fastest at the mix station.
  • In the app — open the Inventory tile and tap Log. Always available to anyone signed in with inventory access.

Either way you land on two big, glove-friendly buttons: Log a spray / usage or Restock.

Step 2a — Log a spray / usage

A short form:

  • Product — a fast search / type-ahead picker over the inventory, with recent products and a category filter pinned up top since the list is long. This is what replaces scanning a specific item.
  • Amount used (required) — number + unit, with the containers/measured toggle; decimals allowed. Mandatory, so stock always decrements by a real figure.
  • Where — opens the interactive map; the person taps the plots they sprayed (a "plot" = a turf area of one grass type; trials and restrictions live inside plots). This records the exact plots and auto-sums the total area treated from the map's plot sizes. When logging from a task, the plots pre-fill from that task.
  • Who / when — auto-filled from login and the current time (both editable).

Save → stock is decremented by the amount, and the entry (product, amount, plots, area, who, when) also feeds the chemical-application record.

Depends on the interactive map: the "where" picker and the treated-area total both read from the interactive maps module — plots and their sizes come from there. Until that module is built, "where" falls back to picking plot numbers from a list, without the automatic area total.

Step 2b — Restock

An even shorter form:

  • Product — same search picker; if it's brand-new, + Add product opens item setup with brand-name autofill (§3).
  • Container size + quantity received — pick which size came in (for mixed-size products), then the number of containers (usually whole); auto-converted to a measured amount.
  • Who / when — auto-filled, editable.

Save → stock is incremented. Every movement — usage or restock — is stamped with who, what, how much, and when.

6. Low-stock alerts

Each item has a reorder threshold. When on-hand stock drops to or below it, the item shows a LOW flag on the inventory list — visible to everyone who can see inventory (techs, grads, faculty, Bill, and any granted undergrad), so anyone who spots it can give Bill a heads-up.

No push. Instead, the next time Bill opens the app he sees an in-app alert — a banner / badge summarizing what's low — so it catches him without pinging his phone. He can dismiss it or jump straight to the low-stock list. The alert is Bill's, since he owns reordering.

7. Screens (v1)

  1. Inventory list — items by category, searchable, low items flagged, with the containers/amount toggle, and a Log button (usage/restock) so logging works entirely in-app without the QR. Default screen.
  2. Item detail — stock, location, active ingredient, movement history, and Log usage / Restock buttons.
  3. Log usage / restock — the scan-or-pick → amount flow (§5).
  4. Add / edit item — Bill sets product, category, container type/size, threshold, location. Bill only.
  5. Low-stock view — Bill's list of everything at/below reorder point. Bill only.

9. Out of scope for v1 (comes later)

  • EPA reg # / lot # / expiration tracking and expired-product flags
  • Cost/pricing, purchase orders, vendor info
  • A formal inventory-usage report / export
  • Multiple storage locations with transfers between them
  • Scanning manufacturer barcodes (v1 uses the single shared logging QR)

10. Decisions

  • Shared QR placement: posted in the chem room, mix station, and Bill's office — all pointing to the same logging screen (plus the in-app Log button as backup).
  • Amount used — required: entering the amount is mandatory on every usage/spray log, so stock always decrements by a real figure.
  • Mixed container sizes: a product can have more than one container size (e.g. a 2.5 gal jug and a 30 gal drum). Stock is tracked as the measured amount (single source of truth); on restock you pick which size came in, and the containers view shows the breakdown by size.
